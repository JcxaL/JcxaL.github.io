Scroll Triggers, not Scroll Scrubbing

A scroll-triggered animation plays for a fixed duration once you cross a threshold — like an Intersection Observer, but declared in CSS. It's a different tool from scroll-driven scrubbing, where progress is welded to scroll position. Scroll down to feel the difference.

↓
Pattern 1

play-forwards / reset

This card animates in every time it enters the viewport, and snaps back to its start state the moment it leaves — a clean slate on every pass. That's the reset action.

Re-triggerable entrance

Scroll away and back — this resets instantly instead of animating in reverse.

Pattern 2

play-once / none

This banner only plays its entrance the very first time it's seen. After that, the none exit action means leaving and re-entering the viewport does nothing — it just stays settled. Good for intros that shouldn't repeat and annoy a scrolling reader.

Trigger vs. scrub, side by side

The left box uses a scroll-driven timeline — the shape's position is a direct function of scroll offset, so it can move backwards. The right box uses a scroll trigger — a fixed 550ms animation that fires once per threshold-crossing, independent of scroll speed or direction.
