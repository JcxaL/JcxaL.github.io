The Multi-Column Reader

On turning CSS text flow into pages

Long before browsers had a masonry grid or a bento layout, print designers were already solving the same problem: how do you pour a river of text into a fixed page without losing the reader's place? Newspapers answered with columns. Web CSS answered, eventually, with columns.

Set columns: 2 240px on a fixed-height box and the browser does the typesetting for you — text fills the first column top to bottom, then wraps into the next, exactly like a printed page. Give that box overflow-x: auto and scroll-snap-type: x mandatory and each screenful becomes a snap point, turning a static article into something you can page through.

"Chrome 145 goes further, adding column-wrap and column-height so columns can flow top-to-bottom and wrap into a new row — turning the trick into a real vertical pager."

This demo uses the widely-supported version of the technique — horizontal column overflow with scroll-snap — so it works everywhere today. Try the arrows below, or swipe. Switch to "Single page" in the debug panel to read one column at a time, or drag the sliders to see how the pagination recalculates live as text reflows.

Drop caps, pull quotes, and column rules are all native CSS too — no JavaScript pagination library required for any of it, just ::first-letter, break-inside: avoid, and a column rule.

Keep scrolling sideways: this article is intentionally long enough to span several pages, so you can feel how consistent the page rhythm stays regardless of how much text is on each one.

That consistency is the whole appeal. A masonry grid rearranges itself unpredictably; a magazine-style column pager always gives you a clean, evenly-sized page, the same promise print always made.

And because it's just text flow, accessibility comes for free — screen readers, find-in-page, and text selection all work exactly as they would in a normal document, which is more than most JavaScript pagination libraries can say.
