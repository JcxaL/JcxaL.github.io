The browser's own marker pens

Find-in-page, the spell-check squiggle, the grammar dots, your selection — the engine has always painted these, and you were never allowed to touch them. The highlight pseudo-elements changed that. They accept a deliberately tiny property set — colour, background-colour, text-decoration, text-shadow — and nothing that could move a glyph.

Treatment

Each option restyles only what the spec allows: colour, background, decoration, shadow.

Live find ::highlight(find) + ::search-text

0 matches

A highlight is not an element. It is a range the engine paints over live text, which is why the highlight pseudo-elements exist at all: there is no box to select, only a decoration to describe. The custom highlight registry takes the same idea and hands you the keys — build a Range, drop it in a Highlight, register it under a name, and style it with ::highlight(name).

Because a highlight never reflows, the property set is deliberately small. You may repaint a highlight; you may not resize one. Try the treatments on the right: solid block, marker pen, wavy ink, glow — every one of them is a colour and a decoration, and the text underneath never moves a pixel.

Now press ⌘F or Ctrl+F and search this page for the same word. In a browser that ships ::search-text, the browser's own find highlight arrives wearing the amber treatment too, and the active match picks up the teal underline.

Where the line is drawn. Highlight pseudos cascade by priority, not by specificity: selection sits above search, which sits above spelling and grammar, so overlapping ranges compose predictably instead of fighting. And because they only ever repaint, a highlight can never trigger layout — which is exactly why find-in-page could be opened up to CSS at all.
