Bleed Control

One grid definition, four named lanes. Every block below opts into content, popout, feature or full by name — no wrapper divs, no negative margins. Click any block to move it out a lane.

The columns are named in pairs — [full-start] … [full-end], [feature-start] … and so on — so a child only has to say grid-column: feature. The reading measure stays capped with min(52ch, 100% - 2rem) while the outer tracks absorb whatever space is left.

“A popout is the same grid, one lane wider. Nothing about the block itself changes — only which named line it starts and ends on.”

Because the lanes are part of one grid, blocks stay aligned to each other at every width. Change the measure or the edge gap in the panel and the entire article re-flows together, including the full-bleed strips.

Full-bleed is where this pattern usually breaks. The old trick reaches for 100vw, which counts the scrollbar and ignores any container the element sits inside — so it overflows by a few pixels on Windows, and by a lot inside a narrow parent.

full lane — edge to edge, still inside the same grid

The fix below swaps viewport units for container query units: inline-size: 100cqi with margin-inline-start: calc(50% - 50cqi), measured against a real container instead of the window.

width: 100vw — overflows its container
inline-size: 100cqi — fits exactly
