FUNCTION ARGS

DROP 05 · COMPONENT

A component system
made of four functions

Not a preprocessor. @function defines real CSS functions with typed parameters, defaults and local variables — so a design system stops being a wall of custom properties and starts being calls like --tone(var(--hue), 0.78) and --elevation(3).

THE FOUR DEFINITIONS

Everything below is styled with these and nothing else. Move the sliders — you're changing arguments, and every call site re-resolves.

/* one function, every surface colour */ @function --tone(--h, --l, --c: 0.14) { result: oklch(var(--l) var(--c) var(--h)); } /* a shadow scale with local variables */ @function --elevation(--n) { --blur: calc(var(--n) * 7px); --lift: calc(var(--n) * 2px); --alpha: calc(0.10 + var(--n) * 0.07); result: 0 var(--lift) var(--blur) rgb(0 0 0 / var(--alpha)); } /* fluid type without memorising the clamp incantation */ @function --fluid(--min, --max, --from: 22rem, --to: 70rem) { … } /* corners that scale together */ @function --corner(--r, --scale: 1) { result: calc(var(--r) * var(--scale) * 1px); }

01 · BUTTONS

Four variants, one rule each. The hover and active states just pass a different --n into --elevation().

02 · CARDS

Same functions, bigger surfaces — --corner() takes a scale factor so a card's radius stays proportional to a button's without a second token.

TYPED

Parameters

Arguments can declare a syntax, so the browser rejects a colour where a length belongs.

DEFAULTS

Fallbacks

A default value after the colon means most call sites pass two arguments instead of five.

LOCALS

Bodies

A function body can declare its own custom properties and even carry @media blocks that change what result resolves to.

03 · A TONE RAMP

Six calls to --tone() with the same hue argument. Drag the hue slider and the entire system re-tints — buttons, cards, pills and ramp together.
