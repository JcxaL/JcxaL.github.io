Clamping, taken apart

-webkit-line-clamp was always one knob: a line count, a forced flexbox, and an ellipsis you could never change. CSS Overflow 4 splits it into three honest longhands — continue, max-lines and block-ellipsis — and each card below sets a different one.

DEFAULT MARKER

A cam profile is not a drawing of a shape; it is a drawing of a schedule. You decide when the follower should move and how gently it should get there, and the outline is whatever falls out of that decision. Designers who start from the outline almost always end up with a jerk discontinuity they cannot explain.

continue: collapse; max-lines: var(--lines); block-ellipsis: ellipsis;

CUSTOM STRING

The marker has never been yours to choose. Every design system that wanted “read more” at the clamp point rebuilt the whole truncation in JavaScript, measured line boxes by hand, and then broke the moment someone resized the window or the font loaded late.

continue: collapse; max-lines: var(--lines); block-ellipsis: " — keep reading →";

NO MARKER

Sometimes the cut should be silent. A card grid where every tile ends in a trailing ellipsis reads as broken rather than abbreviated, and the ellipsis is doing no work the layout was not already doing.

continue: collapse; max-lines: var(--lines); block-ellipsis: no-ellipsis;

CLAMP BY HEIGHT

The count was never the real constraint — the box was. max-lines: auto says so out loud: fill the block size you were given, then stop, whatever the line height, the font, or the translation happens to be. The line count was only ever a proxy for this.

continue: collapse; max-lines: auto; block-size: 7.2em;

The tell: drag the slider. Where the longhands ship, the marker in card 2 is a real block-ellipsis string placed by the layout engine, and card 3 cuts without a marker at all. Where they don't, both fall back to -webkit-line-clamp — which can count lines but cannot be told what to put at the end, so the string has to come back as a ::after that the clamp doesn't actually know about.
