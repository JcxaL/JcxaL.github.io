Micro-interaction · Drop 4

Hover Intent

A tooltip that appears the instant your cursor crosses it is noise; one that always makes you wait is sluggish. The fix is two timers and a shared flag: wait before the first open, then treat the whole group as warm so every neighbour opens immediately — and keep a grace window on the way out, so travelling into the panel never dismisses it.

1 · Five chips, one shared intent

Sweep across quickly — nothing flashes. Rest on one: the ring fills, it opens, and now the other four are instant.

The ring is the delay made visible. Real products hide it; it is here so you can watch the timer you are tuning.

2 · A menu bar that behaves like a desktop one

Open one menu, then slide sideways — neighbours swap with no delay, because the group is warm. Leave the bar entirely and the warmth expires.

3 · Inline in dense content

This is where an eager tooltip hurts most: reading a table means dragging the cursor across a dozen triggers on the way to the one you wanted.

The whole mechanism

enter(el){
  if (group.warm) return open(el);              // a neighbour already broke the ice
  clearTimeout(closeTimer);
  openTimer = setTimeout(() => open(el), OPEN);   // 420ms of intent
}
leave(el){
  clearTimeout(openTimer);
  closeTimer = setTimeout(() => {                    // grace: travel into the panel
    close(el);
    warmTimer = setTimeout(() => group.warm = false, WARM);
  }, CLOSE);
}

CSS is growing native properties for exactly this — interest-delay-start and interest-delay-end — and they are applied here wherever the engine already has them.

4 · The same row with no intent at all

For comparison: zero delay, zero grace, no shared warmth. Sweep across it once and the difference stops being theoretical.
