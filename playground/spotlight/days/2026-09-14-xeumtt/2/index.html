Clip Is Not Hidden

They look identical and they are not. overflow: hidden quietly turns a box into a scroll container — scriptable, focus-scrollable, and fatal to any position: sticky inside it. overflow: clip just clips, and it brings overflow-clip-margin, which lets a hover lift escape the box while the other axis stays clipped. Chrome 153 finally lets you mix the two per axis.

1 · One of these boxes can scroll

Press Scroll both boxes. Same markup, same size, one property apart — the red line is 64px below the fold.

overflow: hidden
visible linescrollTop can move this box…
…all the way down to here.
overflow: clip
visible linescrollTop does nothing at all…
…so this stays unreachable.
scrollTop — hidden: 0 · clip: 0

A box that scrolls when you never asked it to is how content ends up visually lost but still in the tab order.

2 · Sticky dies inside hidden

Scroll each list. The left header is stuck to a wrapper that became its own scrollport, so it never sticks to the list you are scrolling.

wrapper: overflow hidden
▸ header (hidden wrapper)
wrapper: overflow clip
▸ header (clip wrapper)

3 · Clip with a licence to bleed

A horizontal rail clipped on the block axis. Hover a tile — with overflow-clip-margin the lift and its shadow escape the box; set the slider to 0 and the same hover gets guillotined.

overflow: auto clip · overflow-clip-margin: var(--bleed)
the same rail with overflow-clip-margin: 0

4 · The two-value trap

Computed live in your browser right now. A scrolling value on one axis drags visible on the other axis to auto — clip is the only value that lets visible stay itself.

you writeoverflow-xoverflow-ywhat happened

This is why overflow-x: hidden on a wrapper so often breaks sticky and adds a stray vertical scroller you never asked for.
