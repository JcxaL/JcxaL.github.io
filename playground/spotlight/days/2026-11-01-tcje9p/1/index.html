Animation · Drop #1

An animation that plays, not one that scrubs

Scroll-driven animation ties progress to the scrollbar: scroll back and it rewinds, stop halfway and it sits halfway. A trigger is the other thing people actually wanted — cross a line, and a normal timed animation starts and runs at its own pace. Two new properties split the job: one element declares the tripwire, another says what to do when it is crossed.

Native timeline-trigger + animation-trigger detected: checking…

Scroll. Each band below uses a different pair of enter / exit actions.

Once, and never again play-once none

The classic reveal. It plays the first time the band is crossed and ignores every crossing after, so scrolling back up does not replay it.

LedgerBalances reconciled nightly against the clearing file.once
DispatchRoutes recomputed when a vehicle drops off the mesh.once

Restart every time replay none

Sets progress back to zero and plays again on each entry. Scroll past, come back, and the stagger runs from the top — useful for a band you want to feel alive on every visit.

SignalsEvery interlocking reports its state twice a second.replay
HeadwayGaps between services, smoothed over a rolling hour.replay

Forward in, backward out play-forwards play-backwards

The exit action flips the playback rate instead of jumping. Leaving the band un-plays the animation at its own speed — which looks nothing like scrubbing, because the timing function still applies in reverse.

DraughtHull displacement sampled at four points.reversible

Run while visible play pause

Enter plays at the current rate, exit pauses where it stands. Nothing resets, so the animation picks up mid-stride the next time the band comes back into view.
