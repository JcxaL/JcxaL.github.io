Columns that wrap into rows

Constrain a multicol container’s height and the extra columns used to march sideways, dragging a horizontal scrollbar with them. Level 2 gives the overflow somewhere to go: down.

Instance 1 — long-form article ·

The second row of a newspaper

Print has set type in stacked rows of columns for four centuries, because a reader’s eye prefers a short line to a long one and a page prefers to be a page rather than a scroll. The web spent its first decades unable to express that: a multicol container with a fixed height pushed its surplus columns sideways, out past the edge of the viewport, and the layout quietly turned into a horizontal scroller.

With a column height declared, each row of columns is filled to that height and the remainder begins again at the left, one row further down. The gap between those rows is an ordinary row gap, so the same spacing vocabulary that grid and flex use applies here too.

The trade is readability of a different kind: a reader who does not notice the row break will skip from the bottom of the last column back up to the top of the first, and lose the thread. Rules, rows of leading, or a visible marker between rows earn their keep here.

Because the columns are still a single flow, nothing about the content model changes. Text, figures and spanning headings behave exactly as they did; only the geometry of the overflow is new.

That makes it one of the rare layout features that can be added to an existing page as pure enhancement: browsers without it keep the old sideways behaviour, and browsers with it simply stop scrolling horizontally.

Instance 2 — short column height, denser rows

Set the column height low and the same paragraph breaks into many small rows, which reads like a contact sheet of text. Useful for captions, indexes, or a credits roll where the eye scans rather than reads.

Each row is exactly the declared height even when the last one is only part full, so a grid of text blocks stays on a predictable rhythm down the page.

A row rule will eventually be drawable through the gap decorations work, which is the missing half of this feature: the row break needs to be visible to be read correctly.

Instance 3 — block-direction carousel

Pocket-sized rows make a deck: every row of columns is one screenful, and scrolling moves between rows rather than along them.

Pair the same declaration with scroll snapping on the block axis and the multicol container becomes a paginated reader without a line of script.

The content remains one continuous flow, which means find-in-page, selection and screen readers still see a single article.

That is the quiet advantage over faking pages with transforms: nothing is cloned, nothing is absolutely positioned, and the text never leaves normal flow.
