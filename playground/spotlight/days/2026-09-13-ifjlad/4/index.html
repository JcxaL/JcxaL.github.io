Hover physics you can name

A tasteful hover is never one property — it is a lift, a tilt, a glow and a press, all derived from the same pointer value, and all tuned together. Until now that maths lived in a Sass mixin or a JS helper. @function puts it in CSS: declare --lift(), --tilt-x() and --glow() once, with default arguments, and every card and button on the page calls them. Retune the feel by editing one result line.

Before — the maths is inlined, five times

Every element repeats the same calc chain. Change the feel and you change it everywhere, by hand.

.card:hover{ transform: translateY(calc(var(--t) * -10px * var(--force))) rotateX(calc(var(--dy) * 9deg * var(--force))); } .btn:hover{ transform: translateY(calc(var(--t) * -6px * var(--force))); }

After — the maths has a name

Arguments carry defaults, so a call site only states what differs from the house feel.

@function --lift(--t, --max: 10px) { result: calc(var(--t) * var(--max) * var(--force) * -1); } .card:hover{ transform: translateY(--lift(var(--t))); } .btn:hover { transform: translateY(--lift(var(--t), 6px)); }
@function --glow(--t, --hue: 42) { result: hsl(var(--hue) 95% 60% / calc(var(--t) * .55 * var(--force))); } .button { box-shadow: 0 10px 26px --glow(var(--t)); } .button.rose { box-shadow: 0 10px 26px --glow(var(--t), 340); }
