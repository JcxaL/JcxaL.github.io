Spring

Motion you declare, not animate

No per-element JavaScript. Each element states what it wants in CSS — --k-tilt, --k-magnetic, --k-repel, --k-drag — and one spring loop writes back --k-x, --k-y, --k-rx, --k-near. Because they are registered with @property, the rest of the rule is ordinary CSS.

--k-tilt

Three cards turning toward the pointer. The glow and shadow read var(--k-near), which the same loop supplies.

Nearness is a numberThe engine only writes values. Every visual decision stays in the stylesheet.--k-tilt: 12
Stronger tiltOverride the property on one element and nothing else changes.--k-tilt: 20
Barely thereA subtler lean for dense layouts, same code path.--k-tilt: 6

--k-magnetic

Four buttons leaning into a nearby pointer at four different strengths — and keyboard focus mirrors hover.

--k-repel

Thirty-six dots that get out of the way. One loop, one spring per dot, no listeners per element.

--k-drag

Throwable chips: drag, let go, and the same spring carries the overshoot home.
